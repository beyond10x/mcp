# Named behavioral obligations for the actual MCP tools/HTTP boundary

These are provisional, source-grounded scenario specifications, **not executable ESS scenario files and not passing tests**. The partial constructor manifest is described in [coverage.md](coverage.md); it covers only a subset of these obligations and no fixture/target exists for this draft yet. A future target must call the real public methods, retain their actual errors/returns, and independently observe remote exchanges. It must not decide the outcome itself from this prose. All source citations are relative to MCP commit `51b9c7969def3dc0fbee9026cd26f4ce5837d62c`, whose runtime matches the adopted baseline.

`T` means `crates/b10x-mcp-types/src/lib.rs`; `C` means `crates/b10x-mcp-client/src/lib.rs`. Use `Limits::default()` unless an exact bound is selected. Defaults at T:66–76 are frame 1048576, tools 512, descriptor 65536, arguments 65536, result 262144, pages 128, request timeout 30s. Only name limits that the invoked path actually enforces. JSON lengths below are `serde_json::to_vec(value).len()`, not original request bytes.

## Real HTTP client boundary

Use an owned loopback HTTP fixture with explicit request counters, bounded response bytes and joined teardown; no external provider or consumer Connectors owner is involved. The existing controlled server proves a starting seam, not all rows below. A wrapper implementing rmcp's `StreamableHttpClient` must forward actual HTTP to that fixture and count actual exchanges; it must not substitute the library's negotiation/dispatch/result logic. A fixture's own chosen read-only tool is test data: the library's general tools/call may mutate upstream state.

## Explicitly outside these deciding scenarios

Legacy discovery fallback/mismatch, InputRequired/task/unknown response variants, close/drop/loss semantics and effective HTTP paging/SSE bounds need pinned SDK forms and fixtures before an executable acceptance assertion. Current wrapper does configure preferred2026-07-28/legacy2025-11-25 and names input-required/tasks/unknown-tools-call-response errors (C:71–85,196–199); this is source evidence, not compatibility test completion. Close uses a 3s SDK timeout (C:90–96); no persistent transition or child lifecycle is inferred. Stdio process authorization, OAuth state/custody and caller assignment remain out of this first HTTP slice.
